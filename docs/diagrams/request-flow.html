Flujo de request, Docker y despliegue

De un click del cliente a la respuesta HTTP, y de un git push a producción. Ver docs/REQUEST_FLOW.md.

GET /api/v1/posts/{slug} — público
1
DispatcherServlet
recibe el request
↓
2
SecurityFilterChain
permitAll() para GET público — pasa directo
↓
3
PostController.detail(slug)
↓
4
PostService.findPublishedBySlug()
@Transactional(readOnly=true)
↓
5
PostRepository
filtra status == PUBLISHED; si no, 404
↓
6
Mapeo a PostDetailDto
dentro de la transacción (Post.tags es lazy, open-in-view=false)
↓
200 OK — JSON
POST /api/v1/admin/posts — admin
1
DispatcherServlet
↓
2
JwtAuthenticationFilter
valida firma del JWT, puebla SecurityContext con ROLE_ADMIN
↓
3
hasRole("ADMIN")
sin token válido → 401
↓
4
Bean Validation sobre PostRequest
@NotBlank/@NotNull fallan → 400
↓
5
AdminPostController.create() → PostService.create()
resuelve tagIds; alguno inválido → 400
↓
6
save() — slug duplicado
GlobalExceptionHandler traduce UNIQUE → 409
↓
201 Created — PostDetailDto
Build — Dockerfile multi-stage
Stage 1 — build (JDK)
eclipse-temurin:17-jdk
dependency:go-offline (cachea deps)
package -DskipTests
→
Stage 2 — runtime (JRE)
eclipse-temurin:17-jre
solo copia el .jar
ENTRYPOINT java -jar app.jar
-DskipTests: los tests necesitan Neon real, no hay perfil de test — nunca corren dentro del build de imagen.
Despliegue — sin pipeline en este repo
git push a main
→
Render (integración nativa con GitHub)
clona el commit, construye con el Dockerfile
→
Deploy
reemplaza la instancia anterior
No hay .github/workflows ni render.yaml — el trigger vive en el dashboard de Render, no en código. Logs/historial: Render → servicio → Events/Logs.
